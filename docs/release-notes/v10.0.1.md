# v10.0.1 — 2026-08-30

Lockstep patch. **EIT schedule completion fix** for `dvb-si`: the collector
used `last_section_number` for completion but ignored
`segment_last_section_number`, so sparse broadcasts (segments with fewer
than 8 sections populated) never completed. The other lockstep crates bump
to 10.0.1 for lockstep parity only — no source change.

## Fixed (dvb-si)

- **EIT schedule collector never completed on sparse broadcasts** (#971).
  `segment_last_section_number` (EN 300 468 §5.2.4) was parsed but not used
  in the completion check — the collector demanded all
  `last_section_number + 1` sections even when a sparse 3-hour segment
  declared only its first section present. Completion now tracks each
  8-section segment's own declared range independently.
